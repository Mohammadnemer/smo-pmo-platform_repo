# Session F1

## Session ID

F1

## Scope

Vite + React + TypeScript SPA scaffold: routing, TanStack Query, and MSAL
auth against Entra External ID, with folders mirroring the six backend
modules (Platform, SMO, PMO, Workflow, Rollup, Notifications). Deliberately
excludes the branded RTL shell, design system, and real module screens —
those are F2, F3, and F4–F9.

## Done when

The app boots and login redirects to Entra and returns authenticated.

## Prerequisites

- B2 (JWT bearer auth on the API) for the audience/scope the SPA requests.
- Node 24 / npm 11 available locally.

## Decisions made

- Scaffolded with `npm create vite@latest -- --template react-ts` (React
  19.2, Vite 8, TypeScript 6, oxlint) rather than hand-rolling config.
- `src/` is organized as `app/` (bootstrap, providers, routes), `auth/`
  (MSAL config, instance, `ProtectedRoute`), `shared/` (query client, API
  fetch helper), and `modules/{platform,smo,pmo,workflow,rollup,notifications}`
  — one folder per backend module, each holding a `pages/` stub for now.
- Auth: `@azure/msal-react`'s `MsalAuthenticationTemplate` with
  `InteractionType.Redirect` wraps the whole router, so any unauthenticated
  visit immediately redirects to Entra — no separate login page/button.
  `initializeMsal()` runs `PublicClientApplication.initialize()` and consumes
  the redirect response before the app renders (required by msal-browser v5).
- Entra client ID/authority/scope and the API base URL are read from
  `import.meta.env.VITE_*` (see `.env.example`), defaulting to the same
  placeholder values B2 used server-side, since the real Entra app
  registration doesn't exist yet.
- TanStack Query is wired end-to-end via a `useHealthQuery` hook hitting the
  API's anonymous `/health` endpoint — proves the query client + fetch +
  dev proxy chain works without reaching into any real module's data.
- `vite.config.ts` proxies `/api/*` to `http://localhost:5080` (the API's
  dev port) so the SPA can call relative paths with no CORS setup needed;
  production routing is a T2/T3 concern.
- `AppShell` (top bar + nav + sign-out) is a functional placeholder only,
  built with logical CSS properties (`padding-inline`, `border-block-end`,
  `margin-inline-end`) per the i18n non-negotiable — it is not the branded,
  RTL-mirrored shell from the design prototype, which is F2/F3 scope.
- Removed `@azure/msal-browser`'s `storeAuthStateInCookie` cache option —
  it no longer exists in v5 (IE11 support was dropped upstream).
- Root `.gitignore`'s `*.env` pattern doesn't match `.env.local`
  (Vite's convention); added `.env.local` and `.env.*.local` explicitly.

## How it was verified

- `npm run build` (`tsc -b && vite build`) — passes clean.
- `npm run lint` (oxlint) — no findings.
- `npm run dev`, then a headless Playwright check against
  `http://localhost:5173/`: the app renders with zero console errors and
  MSAL automatically redirects the browser to
  `https://login.microsoftonline.com/tenant-id/oauth2/v2.0/authorize` with
  the configured `client_id`, `scope`, and `redirect_uri` — confirming the
  scaffold, routing guard, and redirect flow all fire correctly end to end.
  (Playwright was a throwaway dev dependency for this check only; removed
  afterward — it isn't part of the project's tooling.)
- Completing an actual sign-in and hitting `/me` can't be verified yet: no
  real Entra External ID tenant/app registration exists (see B2 follow-ups).
