# Session F2

## Session ID

F2

## Scope

react-i18next with an AR/EN switch, logical CSS, and a fully mirroring layout
and nav — replacing F1's functional-placeholder `AppShell` with the branded,
RTL-mirrored shell from the design prototype (`Bilingual App Shell.dc.html`).

## Done when

Switching to Arabic flips the whole shell correctly, with no hard-coded
left/right.

## Prerequisites

- F1 (SPA scaffold, routing, MSAL auth) — `AppShell` and logical-property
  groundwork already in place to make this swap mechanical.

## Decisions made

- `react-i18next` + `i18next`, resources bundled as static JSON
  (`shared/i18n/resources/{en,ar}.json`) rather than an HTTP backend — the
  string set is small and this keeps MVP lean (no extra runtime fetch/CDN
  dependency for translations).
- `shared/i18n/i18n.ts` is the single place that syncs `<html lang>` /
  `<html dir>` with the active language and persists the choice to
  `localStorage` (`smo-pmo-lang`). It's imported once, for its side effects,
  at the top of `main.tsx` before the app renders.
- Direction mirroring is done entirely with logical CSS properties
  (`padding-inline`, `inset-inline`, `border-inline-end`, `text-align: start`,
  …) plus the `:dir(rtl)` pseudo-class for the handful of icons that encode
  reading/motion direction (collapse chevron, breadcrumb separator, the
  workflow nav icon). No per-language JS branching exists in `AppShell.tsx`
  itself beyond the language-toggle button — one `dir` switch mirrors nav
  side, top-bar clusters, search icon, active-item indicator, and icon flips,
  matching the design prototype's mirroring rules.
- The nav-collapse chevron's direction depends on two independent things
  (collapsed state and text direction) that would otherwise require the
  design prototype's per-language `enChevTf`/`arChevTf` branching. Composed
  instead via a `--flip` CSS custom property set from JS (collapse state
  only) combined with a `:dir(rtl) { transform: scaleX(calc(-1 * var(--flip)))
  }` override — the two scaleX(-1) flips cancel out correctly in every
  combination without any language-aware code.
- Brand/theme tokens (`--brand`, `--surface`, `--text-dim`, etc.) were added
  to `index.css` as static light-theme defaults copied from the design
  prototype's palette — enough to make the shell look finished now. Making
  them tenant-configurable, adding the dark pair, and building a component
  library are explicitly F3 (Design system & branding) scope, not repeated
  here.
- Scoped the nav to the app's 6 real module routes (Home, Strategy, Projects,
  Workflow, Roll-up, Notifications) rather than reproducing the design
  prototype's fictional PMO-workspace chrome verbatim (the top SMO/PMO/
  Executive pill switcher, and side-nav items like Portfolios/Programs/
  Schedule/Resources/Budget/RAID/Admin). Those represent screens that don't
  exist yet and are explicitly F6 (PMO project screens) and later sessions —
  adding nav entries with nowhere real to go would be a half-finished,
  scope-creeping feature. The chrome (top bar, collapsible side nav,
  breadcrumb, RTL mirroring, i18n) is F2's job; the information architecture
  it will eventually carry is not.
- Translated the F1 page stubs' existing placeholder text too (all six
  `modules/*/pages/*.tsx`), since it was in scope for "no hard-coded
  left/right" style completeness and cost nothing extra — did not add any new
  page content/widgets (that stays out of scope per F4/F6/F9).
- Added the IBM Plex Sans / IBM Plex Sans Arabic Google Fonts `<link>` to
  `web/index.html` to match the design prototype's typography — a two-line
  addition directly tied to shell fidelity, not a general design-system pull.

## How it was verified

- `npm run build` (`tsc -b && vite build`) — passes clean.
- `npm run lint` (oxlint) — no findings.
- Temporarily bypassed `ProtectedRoute` in `app/routes.tsx` (no real Entra
  tenant exists to sign in against, same limitation as F1) and used a
  throwaway Playwright script against `npm run dev` to screenshot the shell
  and assert `document.documentElement.dir`/`lang`. Confirmed: `dir` flips
  `ltr` → `rtl` and `lang` flips to `ar` on clicking the AR toggle; the side
  nav, active-item indicator, breadcrumb, top-bar clusters, and icon
  directionality all mirror correctly with no layout breakage; the
  nav-collapse toggle still works correctly in RTL. The `ProtectedRoute`
  bypass, the Playwright dev dependency, and the verification script were all
  reverted/removed afterward — none of it is part of the deliverable.
