# Session B1

## Session ID

B1

## Scope

Implement the request pipeline for tenancy so an authenticated request can resolve a tenant from its JWT claim and make that tenant available to the rest of the application through a scoped tenant context.

## Done when

Tenant_id flows from the JWT all the way to the Postgres connection.

## Prerequisites

- The D1–D4 database foundation must already be present.
- The solution must build successfully with the new middleware in place.

## Decisions made

- Added a shared tenant-context abstraction in the Shared layer so modules can depend on tenancy without depending on Platform.
- Added a request middleware in the API layer that reads the tenant_id claim from an authenticated user and stores it in the shared tenant context.
- Registered the middleware and tenant context in the ASP.NET Core pipeline so every request can resolve tenant context early.
